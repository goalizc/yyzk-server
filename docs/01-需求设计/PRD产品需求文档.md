# PRD — 售后自助故障诊断系统（一期 MVP）

## 1. 产品概述
面向公司产品终端用户的 Web 自助故障查询系统。用户选定产品（可再按零件收窄）后从"故障现象"列表里认出自己的情况，查看结构化解决方案；解决不了一键转工单。

## 2. 用户角色
| 角色 | 描述 | 数据范围 |
|---|---|---|
| 终端用户 | 公司产品的购买者/使用者，通过浏览器访问公开查询页，无需账号 | 仅公开内容 |
| 超级管理员（`super_admin`） | 运维/系统负责人，拥有全部业务功能与账号管理能力 | 全部 |
| 售后主管（`supervisor`） | 内部人员，管理故障知识库、处理与改派工单、看统计 | 全部 |
| 一线客服（`agent`） | 内部人员，处理分配给自己的工单、查知识库 | 仅被授权的产品线 |
| 只读审计（`auditor`） | 内部人员，只读查看工单、产品、零件、故障、看板与用户列表 | 全部 |

### 2.1 权限与临时授权

- 操作权限按 `资源:动作` 的权限码控制（如 `ticket:read`、`ticket:write`、`ticket:assign`、`user:write`），四角色对应固定的权限集合；前端菜单、路由与按钮按权限码渲染，不再按角色名判断。
- 数据权限只作用于**工单**：一线客服只能看到、操作自己产品线下的工单；未分配产品线时看到 0 条并提示联系管理员；无产品归属的工单仅「全部」范围角色可见。知识库在客户侧公开，产品/零件管理不涉及客户数据，因此不做数据范围限制。
- **临时授权**：管理员可对**具体某个人**发放某项操作权限，必须填写**到期时间**（最长 180 天）与事由，到期自动失效，也可提前收回。临时授权**只增不减**，不能剥夺角色已有的权限，也不能授予 `user:write`（避免自我提权）；发放者不能授予自己不具备的权限。
- 工单改派与认领分离：只有持有 `ticket:assign` 的角色（超管/主管）能把工单转给他人；一线客服只能首次认领，没有改派入口。


## 3. 功能需求

### 3.1 客户自助查询（公开，无需登录）

#### F-1 产品选择
- 页面顶部下拉框，列出所有 `is_active=true` 的产品
- 显示产品名称和型号
- 默认提示"请选择产品"
- 选择后触发零件下拉刷新，并**立即显示该产品下全部故障现象**

#### F-2 零件选择（选填）
- 级联下拉，只显示当前产品下的零件
- 按 `group_name` 分组显示（如"电源模块""传感系统"）
- 默认提示"全部零件（不知道是哪个零件就不选）"（即不过滤）
- 未选产品时禁用；产品选中后即可用，但**不要求必选**
- 理由：零件名是维修术语，客户能认出产品型号但拆不到内部部件，强制先选零件会把多数小白客户拦在门外

#### F-3 故障现象列表
- **选完产品即显示**该产品下的故障卡片列表；选了零件则按零件收窄
- 每张卡片显示：故障标题、简短现象摘要、**零件名（参考标签）**、浏览量
- 点击卡片进入详情页
- 列表上方提供**选填的关键词筛选框**（≤ 50 字），**选完产品即可用**：
  - 输入后对当前列表的标题与现象描述做包含匹配，实时过滤
  - 清空即恢复全量
  - 该关键词**不参与跨产品检索**，只缩小当前产品（或产品+零件）的结果
  - 若筛选后无结果，页面展示空态"没有匹配的故障，请换个说法或提交工单"，并记录一次未命中日志（见 F-11）

#### F-4 故障详情
展示内容：
- 故障标题
- 现象详细描述
- 可能原因（根因）
- 分步解决办法：有序列表，每步包含文字说明和可选图片
- 所需工具
- 附件下载（PDF/图片/视频链接）
- 若 `needs_professional=true`：顶部红色警告条"此故障需专业人员维修，请勿自行拆机，建议联系售后"

操作按钮：
- ✅ "问题已解决"：点击后弹提示"感谢反馈"，记录 resolved=true
- ❌ "未解决，联系售后"：跳转工单页，自动带入当前 product_id/part_id/fault_id

#### F-5 工单提交
表单字段：
- 联系方式（手机号/邮箱，必填）
- 称呼（选填）
- 故障补充描述（必填，多行文本）
- 是否需要上门服务（单选：是/否，**必选，默认"否"**）

自动带入上下文：产品、零件、故障标题。
提交后显示：工单号 + 提示"售后会在 24 小时内联系您"。

### 3.2 后台管理（需登录）

#### F-6 登录
- 账号密码登录
- 失败提示"用户名或密码错误"
- 登录成功跳转到工单列表默认页
- 登录响应返回当前账号的**生效权限码**；菜单、路由与按钮按权限渲染
- token 过期自动跳登录页；停用账号的下一个请求即被拒绝

#### F-7 产品管理
- 列表：名称、型号、**产品线**、状态、创建时间
- 新增/编辑弹窗：名称、型号、**产品线（必选下拉）**、描述、排序、上下架开关
- 产品线在独立的产品线管理页维护；产品页提供"管理产品线"入口
- 删除：软删除或硬删除（有关联故障时禁止删除，提示先迁移）

#### F-8 零件管理
- 按产品 tab 切换
- 列表：零件编号、名称、分组、排序
- 新增/编辑弹窗
- 支持拖拽排序（可选，一期用数字排序即可）

#### F-9 故障知识库管理
- 列表：按产品、零件筛选；显示标题、所属产品/零件、查看次数、是否发布
- 编辑器：
  - 基本信息：所属产品（必选）、所属零件（必选）、标题、现象描述、根因
  - 解决步骤：动态列表，可增删行；每行包含步骤说明 + 图片上传
  - 其他：所需工具、是否需专业人员（开关）、附件上传（多个）、是否发布（开关）
- 保存后前台实时可见（is_published=true）

#### F-10 工单管理
- 列表：工单号、产品、联系人（脱敏）、状态、创建时间
- 筛选：状态、时间范围（起止日期）、关键词（工单号/联系方式）
- **数据范围**：一线客服只能看到和操作自己产品线下的工单；过滤先于搜索，关键字也只在可见范围内匹配；详情与更新同样校验，越权返回 403
- 详情面板：完整上下文（产品/零件/故障/用户描述/是否上门）+ 处理备注输入框 + **处理人** + **状态变更历史（谁在什么时候改成了什么）**
- 状态流转：open → processing → resolved / closed
  - open 可转 processing / closed
  - processing 可转 resolved / closed
  - resolved 只能转 closed（重新处理需新建工单）
  - 非法流转直接拒绝并提示
- 流转时记录操作人（自动取当前登录账号，不可手工指定）
- **改派**：仅超管/主管可指定处理人；一线客服只能首次认领，不能转单。候选人只列出启用、有 `ticket:write` 且对该工单产品线可见的账号

#### F-11 数据看板
- 总览卡片（四张，标注统一）：
  - **查询次数**（所选时间窗内）
  - **自助解决率**（所选时间窗内；口径见 §4）
  - **工单总数**（所选时间窗内新建）
  - **待处理工单**（**当前积压**，含"处理中"，不随时间筛选变化，卡片需标注"当前"）
- TOP 10 故障柱状图（按所选时间窗内的查看次数，而非历史累计）
- 未命中检索词表格：检索无结果的记录，按频次排序，展示示例产品/零件与**最近出现时间**
  - 数据来源：用户在关键词框输入后无匹配，或所选产品（+零件）本身没有任何已发布故障
  - 用户未输入关键词的记录单独归为"(未输入关键词)"一行，不与真实关键词混列
- 时间筛选：近 7 天 / 近 30 天 / 全部，对**前三张卡片、柱状图、未命中表格**生效；"待处理"为当前积压不参与筛选

#### F-12 修改密码
- 入口：后台顶栏用户下拉 → 修改密码
- 字段：原密码、新密码、确认新密码
- 规则：新密码 ≥ 8 位，不能与原密码相同，两次输入必须一致
- 成功后提示"密码已修改"，当前会话保持登录
- 目的：保证验收要求的"默认密码必须修改"可自助完成，无需运维介入

#### F-13 用户与权限管理
- 仅超级管理员可新建账号、修改姓名/角色、停用/启用、重置密码、分配产品线与发放临时授权；只读审计可查看列表与授权记录
- 不提供删除用户，只停用（保留历史工单与流转记录归属）
- 硬约束：不能停用自己、不能修改自己的角色、系统至少保留一个在用超管
- 重置密码由服务端生成 12 位密码，仅在响应中展示一次；任何接口不返回密码哈希
- 临时授权按人发放，必填到期时间（≤180 天）与事由，可提前收回；到期后下一次请求即失效

#### F-14 产品线管理
- 产品线字段：名称（唯一）、排序、启用状态
- 新建、改名、排序、启用/停用；仍被产品引用时禁止删除
- 停用后不用于新建产品或新授权，已有产品归属与授权继续有效
- 产品线管理页在侧栏「产品管理」之前提供独立入口（`product_line:read`），同时保留产品管理页与用户管理页的产品线下拉入口

## 4. 非功能需求
| 项 | 要求 |
|---|---|
| 性能 | 结构化查询响应 < 500ms（P95） |
| 并发 | 支持 100 并发用户同时查询（一期足够） |
| 兼容性 | Chrome / Edge / Safari 最近 2 个大版本；移动端响应式 |
| 安全 | 密码 bcrypt；JWT 24h 过期；SQL 注入防护（ORM）；XSS 防护（前端转义，禁止 `v-html` 渲染用户/运营录入内容） |
| 部署 | Docker Compose 一键启动；4 核 8G 服务器可跑 |
| 数据备份 | 数据库每日自动备份；附件目录备份 |
| 时区 | 服务端与数据库统一 `Asia/Shanghai`，接口时间一律带 `+08:00` |
| **指标口径** | **自助解决率 = 所选时间窗内"标记已解决"的查询数 ÷ 该窗口内"查看了方案"的查询数**；此口径为唯一口径，各处看板与汇报均以此为准 |
| **国际化（长期约束）** | 系统支持中文 / English 双语，客户侧由 URL 前缀决定（`/` 中文、`/en` 英文），后台顶栏手动切换。<br>**此后所有新增功能必须同时支持两种语言**：界面文案不得硬编码，一律走语言包；新增后端错误码须同时补两语言文案；表单与表格宽度按英文长度核对。<br>执行细则见 `docs/02-技术设计/国际化设计.md` §11，自动化闸门为 `scripts/dev/check_i18n.py` 与 `e2e/i18n-layout.spec.js` |

> 口径为何这样定：`faults.resolved_count / view_count` 是**历史累计值**，无法随时间筛选变化；而看板明确支持近 7 天/近 30 天，只有按 `query_logs` 逐条统计才能与时间筛选自洽。两个数会不一致，展示时只用前者。

## 5. 边界与约束
- 一期不做用户注册/登录（终端用户不需要账号）
- 一期不做支付
- 一期不做多语言
- 一期不做消息推送
- 一期工单独立运行，不与现有客服系统对接
- **用户与权限管理已提前到一期上线前实施**（四角色、账号管理、产品线数据权限、临时授权，见 §2）；操作日志、知识库审核流、自定义角色仍留三期
- **一期不做自然语言/模糊搜索**：关键词筛选只在当前已选产品（可再按零件收窄）的结果内做包含匹配，不跨产品检索，不做同义词与纠错（二期随 LLM 问答一起做）
- **一期不做故障树引导诊断、移动端小程序、IoT 设备联动**：分别排在二期（故障树/图片识别）与三、四期，与章程 §3 一致
