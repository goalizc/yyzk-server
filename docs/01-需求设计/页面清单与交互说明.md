> **后台列表统一交互（所有列表页都必须遵守）**
>
> | 列表 | 点行（主操作） |
> |---|---|
> | P-12 工单列表 | 打开工单详情面板（**不**用列表行数据凑详情） |
> | P-13 产品 / P-14 零件 | 打开编辑弹窗（只读角色点行无反应） |
> | P-15 故障列表 | 打开方案阅读面板；编辑走行内按钮进 P-16 |

>
> 行内控件（开关、授权标签、操作按钮）**必须阻止冒泡**（`@click.stop`），
> 否则点"删除"会先弹出编辑窗。这条是踩过的缺陷，测试已覆盖（开关、授权标签各一条）。

> **页面总数：14 个**（客户侧 4 + 后台 10）。其中 P-11 是布局壳而非独立内容页；工单详情是 P-12 的详情面板组件、修改密码是 P-11 的弹窗组件，均不单独计页面、不单独占路由。P-19 在侧栏「产品管理」之前提供「产品线」入口（权限 `product_line:read`），同时保留 P-13 与 P-18 的快捷入口。

```
│  [ 请选择零件          ▼ ]             │
│  [ 搜索症状关键词（选填）        ] 🔍   │
│                                         │
│  3 条故障现象，点击查看方案              │
│  ┌─────────────────────────────────┐   │
│  │ 喷洒不出水，喷头无雾化           │   │
│  │ 药箱有药液、App 已开喷洒开关，…  │   │
│  │ 128 人看过                       │   │
│  ├─────────────────────────────────┤   │
│  │ 雾化不良，雾滴粗或有连续滴漏     │   │
│  │ 喷洒时喷头甩出的不是雾而是水滴…  │   │
│  └─────────────────────────────────┘   │
│          [ 展开更多（还有 2 条） ]       │
│  都不是我的情况？  提交工单              │
└─────────────────────────────────────────┘
```

### 交互规则
1. 页面加载时请求 `/api/products` 填充产品下拉
2. 产品选中 → 请求 `/api/products/{id}/parts` 填充零件下拉，**按 `group_name` 分组显示组标题，组内按 `sort_order` 升序**
3. 零件未选时零件与关键词框禁用（置灰 + 提示"请先选择产品"）；产品未选时零件下拉禁用
4. 零件选中 → 请求 `/api/faults?product_id=&part_id=` 渲染**故障现象列表**，每项显示**标题 + 现象摘要 + 浏览量**（摘要最多 2 行，超出省略）
5. 切换产品或零件时，清空后续列表、关键词与展开状态
6. 点击故障条目 → 跳转 `/faults/{id}?q={当前关键词}`（关键词为空时不带 `q`）
7. 关键词过滤是**即时本地匹配**（标题 + 现象，不重新请求），清空即恢复全量；**600ms 防抖只作用于"未命中上报"**，避免每敲一个字就打一次统计接口
   - 说明：接口虽支持 `q` 参数，但前端打字时**不用**它（每次按键都打请求没有必要，单个组合下故障数 ≤ 50）；`q` 仅用于直达链接与外部调用
8. 折叠：默认展示 5 条，点「展开更多」每次再展示 5 条；关键词变化或切换零件时收起回第一屏
9. 空态规则（决定未命中统计是否准确）：
   - 若关键词有值且过滤后为 0 条 → 提示"没有找到匹配的解决方案"，给「清空关键词」与「提交工单」两个按钮，同时 `POST /api/query-logs` 记一条 `raw_query={关键词}`
   - 若关键词为空且接口本身返回 0 条 → 提示"这个零件暂时还没有故障记录"，只给「提交工单」；**选完零件、接口一返回 0 条就记**一条 `raw_query=null`（不等用户输入关键词，否则"未输入关键词"这一桶永远为空）
   - 同一组合 + 同一关键词 30 秒内只记一次，避免重复计数
10. 列表底部固定一行「都不是我的情况？提交工单」：有结果但都不符合时，不逼用户挨个点开找报障入口
11. 移动端：下拉、搜索框和条目单列堆叠；空态的两个按钮竖排整行

### 为什么没有「第三步：选择故障现象」下拉（v1.2 移除）

早期是三级下拉（产品 / 零件 / 故障现象）。实测发现：

- 第三步下拉的选项与下方列表**是同一批数据**，选完还要再点一次「查看解决方案」，同一目标两条路径、两种点击深度
- 下拉里**只有标题**（"雾化不良，雾滴粗或有连续滴漏"），而客户能对上号的是 `symptom`（"喷洒时喷头甩出的不是雾而是水滴"）——最需要判断的一步反而信息最少
- 数据上，**41 个有故障的零件里 32 个（78%）只有 1 条故障**，下拉打开是个单选项

因此第三步改为"列表即选择器"：层级从 3 步降到 2 步，故障数据在页面上只出现一次。
`Home.spec.js`「只有产品与零件两级」用例锁死此决定，加回下拉会先让该用例变红。

## P-11 后台布局

```
┌──────┬──────────────────────────────────┐
│ Logo │ 顶栏：当前用户 ▼                 │
├──────┼──────────────────────────────────┤
│ 工单 │                                  │
│ 产品 │                                  │
│ 零件 │        内容区域                  │
│ 故障 │                                  │
│ 统计 │                                  │
└──────┴──────────────────────────────────┘
```

侧边栏菜单（**按当前账号的权限码渲染，无权限的菜单不显示**）：
- 工单管理（`ticket:read`）
- 故障知识库（`fault:read`）
- 数据看板（`stats:read`）
- 产品线（`product_line:read`）
- 产品管理（`product:read`）
- 零件管理（`part:read`）
- 用户管理（`user:read`，仅超管与只读审计可见）

> **顺序按「日常作业 → 数据分析 → 基础配置 → 系统管理」排列**，不按功能上线先后。
> 产品线 → 产品 → 零件 是数据层级（从粗到细），三项必须连续，中间不插其它项。
> 该顺序由 `Layout.spec.js` 断言锁定，新增菜单要落到正确分区，不要往数组尾部追加。

顶栏用户下拉：
- 当前用户名 + 角色标签（四角色：超级管理员 / 售后主管 / 一线客服 / 只读审计）
- **修改密码** → 弹窗（原密码 / 新密码 / 确认新密码）
- 退出登录 → 清 token 回登录页

修改密码弹窗规则：
1. 三项均必填；新密码 ≥ 8 位；两次输入必须一致；新密码不能与原密码相同（前端校验后仍由后端兜底）
2. "确认新密码"只做前端一致性校验，不提交给后端
3. 原密码错误：在"原密码"字段下方内联提示"原密码不正确"，不关闭弹窗
4. 失败时保留已输入内容（密码框清空），成功后关闭弹窗并提示"密码已修改"
5. 修改成功后不退出登录，当前会话保持有效

> 修改密码弹窗不占独立路由，属于 P-11 的内嵌组件；这是"默认密码必须修改"验收项的唯一入口。

### 交互规则
1. 列表默认按创建时间倒序，状态列用彩色标签；联系人脱敏显示
2. 筛选条件变更即查询，三个条件可叠加；"重置"一键清空
3. 点击行 → 请求 `/api/admin/tickets/{id}` 打开详情面板（**不要**用列表行数据凑详情）
4. 修改状态下拉时按合法路径约束：open→processing/closed，processing→resolved/closed，resolved→closed，closed 不可选
5. 保存后局部刷新列表行与面板，不整页重载
6. 状态变更必须填备注（留痕要求），空备注拒绝提交
7. **数据范围**：一线客服只能看到自己产品线下的工单；未分配产品线时列表为 0 条并提示"尚未分配产品线，请联系管理员"；无产品归属的工单客服不可见。详情与更新同样校验，越权展示 403 提示
8. **处理人下拉**：仅持有 `ticket:assign` 的账号（超管/主管）可见；候选人为启用、有 `ticket:write` 且对工单产品线可见的账号。一线客服没有改派入口，只能首次认领；要转单由主管操作
9. 改派到其他产品线后，原处理人不再能看到该工单（刷新列表即消失）

## P-13 产品管理

### 列表
| 列 | 说明 |
|---|---|
| 名称 / 型号 | 型号唯一，重复时报错 |
| 产品线 | 取自 `line_name`；由独立的产品线管理页维护 |
| 故障数 | 来自 `fault_count`，删除前判断用 |
| 状态 | 已上架 / 已下架（标签色区分） |
| 创建时间 | `YYYY-MM-DD` |

### 弹窗字段
名称*、型号*、**产品线*（下拉）**、描述、排序（数字）、是否上架（开关）

> 产品线下拉拉取全量：已停用的线标注「（已停用）」，新建时不可选；编辑时当前产品所在的停用线仍可选并标注。旁边提供"管理产品线"入口跳转 P-19。新建产品时产品线必填，未选不允许保存。

### 交互规则
1. 新增/编辑共用一个弹窗；编辑时回填，型号撞号返回 409 `MODEL_DUPLICATED`，**在型号输入框下方内联提示**，不整页报错
2. 删除前弹确认框；若 `fault_count > 0`，确认框直接提示"该产品下有 N 条故障，需先迁移"，并禁用"确认删除"
3. 删除请求返回 409 `DELETE_BLOCKED` 时，把 `detail` 原文展示给用户
4. 上架/下架为列表内开关，切换即保存，失败回滚开关状态
5. 保存成功关闭弹窗并局部刷新列表，不整页重载

2. 新增/编辑字段：零件编号、名称*、分组、排序
3. 零件必须归属当前选中的产品，`product_id` 由页面带入，不可跨产品
4. 删除时若有关联故障，返回 409 `DELETE_BLOCKED`，提示故障条数
5. 分组名可自由输入，列表按 `group_name` 分组渲染

## P-15 故障知识库列表

### 筛选栏
产品（下拉）、零件（级联）、关键词、发布状态（全部/已发布/未发布）、[重置]

### 列表列
标题、所属产品、所属零件、查看次数、解决次数、是否发布、更新时间、操作（编辑/删除）

### 交互规则
1. 筛选条件变更即请求（防抖 300ms），分页 20 条/页
2. 点击行 → 打开下方「阅读面板」，**不进入编辑页**；行内「编辑」按钮仍进入 P-16；删除需二次确认
3. 删除故障**不阻止**（被工单引用时置空引用），提示"删除后不可恢复"
4. 列表为空时显示"暂无故障，点击新增录入第一条"
5. 列表接口不返回 `solution_steps`，打开阅读面板或编辑时再单独拉详情

### 阅读面板
点击任意故障行打开「方案详情」面板，内容复用客户侧方案展示组件，与客户侧保持一致：

- 标题，以及「已发布 / 未发布」「需专业」标签
- 产品 / 零件、更新时间、查看次数、解决次数
- `needs_professional=true` 时的风险提示（红色警示条）
- 现象描述、可能原因、所需工具
- 分步图文（按步骤序号升序，图片可点击放大）
- 附件列表（文件名 + 大小，点击新窗口打开）

底部操作：

| 按钮 | 可见条件 | 行为 |
|---|---|---|
| 编辑 | 持有 `fault:write` | 关闭面板并进入 P-16 |
| 复制方案文本 | 方案加载成功 | 按下方规则生成文本写入剪贴板 |
| 打开客户页 | 仅 `is_published=true` | 新窗口打开 `/faults/{id}` |
| 关闭 | 始终显示 | 仅关闭面板，不跳转 |

复制方案文本规则：
1. 文本包含标题、产品/零件、现象描述、可能原因、所需工具与分步步骤
2. 已发布方案在末尾附客户页链接 `/faults/{id}`；未发布方案不附链接，改为「该方案尚未发布，配图请在系统内查看」提示
3. 带图片的步骤在步骤文本后单独一行标注 `[含示意图]`
4. `needs_professional=true` 时首行追加安全警示「该故障建议由专业人员处理，请勿自行拆机」
5. 优先使用 Clipboard API；HTTP 内网或权限被拒时自动退回 `textarea + execCommand` 兜底，仍失败则提示「复制失败，请手动选择文本」

### 布局
```
筛选：[关键词（用户名/姓名）] [角色 ▼] [状态 ▼]        [+ 新建账号]
┌────┬─────────┬──────┬────────┬──────────────┬────────┬──────────┐
│ ID │ 用户名  │ 姓名 │ 角色   │ 产品线       │ 状态   │ 操作     │
├────┼─────────┼──────┼────────┼──────────────┼────────┼──────────┤
│ 1  │ admin   │ 管理员│ 超管  │ —            │ 启用   │ 编辑/重置│
│ 2  │ li      │ 李工 │ 客服   │ 扫地机(长期) │ 启用   │ 编辑/授权│
└────┴─────────┴──────┴────────┴──────────────┴────────┴──────────┘
```

### 交互规则
1. 列表字段：`id`、`username`、`real_name`、`role`、`active_grant_count`、`product_lines[{id,name,expires_at}]`、`is_active`、`last_login_at`、`created_at`；支持关键词、角色、启用状态筛选与分页
2. 新建/编辑弹窗：用户名（新建与编辑均可填；编辑时账号可修改，改名后需用新账号登录）、姓名、角色、初始密码（仅新建，需二次确认一致）、产品线多选（每项可设到期时间）
3. 重置密码：二次确认后弹窗展示**一次性**明文密码 + 复制按钮；关闭后不可再查看。复制失败时提示手动复制
4. 临时授权：权限码下拉**排除 `user:write`**、到期时间（必须晚于当前时间且 ≤180 天）、事由（1–200 字）；下拉与授权记录中权限码显示中文名（如 `ticket:write` → 处理工单），悬停可看原始码；授权记录列表含授予人（`granted_by_name`，为空显示「系统」）、已过期/已收回，可提前收回
5. 角色「临时授权 N」：`active_grant_count > 0` 时在角色下方显示警告色标签，点击直接打开该用户的授权面板
6. 停用账号前二次确认「停用后该账号将立即无法登录」；编辑时若角色发生变化，保存前二次确认「其权限会立即变化」。取消则不发请求，开关与角色保持原值
7. 编辑自己时角色与启用状态置灰；服务端另有自停用、自改角色、最后超管保护兜底
8. 只读审计（`auditor`）可进入本页查看列表与授权记录，但**隐藏**新建/编辑/重置密码/发放与收回授权按钮
9. 产品线分配采用整体替换语义：保存即用当前列表覆盖旧授权；下拉拉取全量产品线，已停用的线标注「（已停用）」，新建/新增分配时不可选，当前已分配的停用线仍保留
10. 详情类面板统一为居中弹窗（`components/DetailPanel.vue`），宽度 `min(桌面宽度, 92vw)`：工单详情与方案详情桌面 880px、授权记录 820px；新建/编辑弹窗桌面 620px、窄屏 92%。所有面板在 360px 视口下无横向滚动
