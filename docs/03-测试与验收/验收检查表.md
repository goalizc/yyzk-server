# 验收检查表

> 上线前逐项打勾，全部通过才能上线。
> 版本：v1.4（2026-10-22）｜ 对应测试用例 87 条（P0 53 / P1 32 / P2 2）

## 一、功能验收
- [ ] 客户能走完"选产品→选零件→看方案→反馈/转工单"全流程
- [ ] 故障列表的关键词筛选可用，无结果时展示空态并引导转工单
- [ ] 后台能完成产品/零件/故障的完整 CRUD
- [ ] 故障编辑器能录入分步图文方案
- [ ] 文件上传（图片/PDF）正常，类型和大小限制生效（超限返回 413）
- [ ] 工单提交后后台可见，状态可流转，**非法流转被拒绝**
- [ ] 工单详情能展示完整上下文、用户描述、**是否需要上门**
- [ ] 工单每次状态变更都记录了**操作人与时间**，详情页可查看完整历史
- [ ] 工单列表支持**状态 + 时间范围**组合筛选
- [ ] 数据看板四张卡、TOP10、未命中表数字与数据库一致，**切换时间范围全部联动**
- [ ] 后台能自助修改密码，无需运维介入
- [ ] 未登录访问后台被拦截
- [ ] 专业维修类故障前台显示红色警告
- [ ] 未发布故障前台不可见（列表与直接访问均不可见）

## 二、数据验收
- [ ] 至少 50 条真实故障已录入
- [ ] 每条故障都关联了正确的产品和零件
- [ ] 至少 3 条故障包含附件
- [ ] 至少 2 条故障标记为 needs_professional=true
- [ ] 至少 1 条真实工单带「需要上门」记录
- [ ] 默认管理员密码已修改（不是初始化密码）
- [ ] 产品/零件/故障的数量与售后团队提供的台账一致

## 三、技术验收
- [ ] `docker compose up -d` 在干净服务器 5 分钟内起服
- [ ] `docker compose ps` 显示 **4 个容器**（db / backend / frontend / nginx）全部 running，db 与 backend 为 healthy
- [ ] `init_admin.py` 在干净库上执行成功，重复执行不报错不重复建号
- [ ] 数据库连接池配置合理（pool_size + max_overflow 有明确值）
- [ ] 日志输出到 stdout，`docker logs` 可见，含请求方法与耗时
- [ ] Nginx 静态资源缓存与 gzip 配置正确
- [ ] SPA 路由刷新不 404（`/admin/faults/edit/1` 直接刷新可正常渲染）
- [ ] 上传目录有持久化卷，`/uploads/` 由 Nginx 直出
- [ ] 数据库时间字段为 `TIMESTAMPTZ`，容器 `TZ=Asia/Shanghai`，接口返回带 `+08:00`

## 四、安全验收
- [ ] 密码 bcrypt 哈希存储，数据库里看不到明文（TC-65）
- [ ] 仓库与镜像中不存在硬编码的真实密码（仅 `.env.example` 的占位值）（TC-65）
- [ ] JWT_SECRET 已改成随机串（不是默认值，长度 ≥ 32）（TC-65）
- [ ] DB 密码已改成强密码（≥ 16 位，hex 生成）
- [ ] **35 个需鉴权端点逐个验证 401**（TC-64 参数化遍历，不接受抽查一个）
- [ ] 文件上传有类型白名单（后缀 + MIME 双重校验）（TC-42）
- [ ] 上传文件名被重命名，路径穿越请求被拒绝（TC-73）
- [ ] 故障与工单内容以纯文本渲染，XSS 用例通过（TC-72）
- [ ] 没有 SQL 注入风险：`q` 与 `keyword` 注入探测通过（TC-66）
