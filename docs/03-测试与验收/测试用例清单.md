## 1. 客户侧功能（16 条）

### TC-01 产品下拉加载
- **前置**：库中有 2 个已上架、1 个已下架产品
- **步骤**：打开首页
- **预期**：下拉显示 2 个已上架产品的「名称 + 型号」，无下架产品
- **优先级**：P0

### TC-02 零件级联与分组
- **前置**：产品 A 有 3 个零件分属 2 个 group，产品 B 有 2 个
- **步骤**：选择产品 A
- **预期**：零件下拉出现 3 项，按 group_name 分组显示组标题，组内按 sort_order 升序
- **优先级**：P0

### TC-03 切换产品重置后续选择
- **前置**：已选产品 A、零件 A1、关键词已输入、列表已加载
- **步骤**：切换到产品 B
- **预期**：零件、故障列表、关键词框全部清空，零件下拉刷新为 B 的零件
- **优先级**：P0

### TC-04 故障列表排序
- **前置**：某组合下有 5 条已发布故障，view_count 分别为 5/50/500/1/20
- **步骤**：选完产品和零件
- **预期**：5 张卡片按 500→50→20→5→1 降序，每张显示标题与现象摘要
- **优先级**：P0

### TC-05 故障详情渲染
- **前置**：一条故障含 3 个步骤，第 1 步有图，含 1 个 PDF 附件
- **步骤**：点击卡片
- **预期**：标题/现象/根因正确；步骤按 1→2→3；第 1 步图片正常加载，缺失图片不破版；附件可点
- **优先级**：P0

### TC-06 专业维修警告（正向）
- **前置**：故障 X `needs_professional=true`
- **步骤**：打开 X 详情
- **预期**：顶部红色警示条，文案为「此故障需专业人员维修，请勿自行拆机，建议联系售后」
- **优先级**：P0

### TC-07 专业维修无警告（反向）
- **前置**：故障 Y `needs_professional=false`
- **步骤**：打开 Y 详情
- **预期**：无警示条，页面布局不下移
- **优先级**：P1

### TC-08 标记已解决（含日志精确更新）
- **前置**：A、B 两台设备各打开同一故障详情一次（产生 2 条 query_logs）
- **步骤**：A 设备点击「问题已解决」
- **预期**：
  - 弹「感谢反馈」
  - `faults.resolved_count` +1
  - **仅 A 的 query_logs.resolved=true**，B 的记录保持 NULL
  - 重复点击不重复计数（按钮置灰或二次点击返回成功但不加数）
- **优先级**：P0

### TC-09 未解决转工单
- **步骤**：详情页点击「未解决，联系售后」
- **预期**：跳转工单页，产品/零件/故障名称正确回显
- **优先级**：P0

### TC-10 工单必填校验
- **步骤**：只填「称呼」，不填联系方式与描述
- **预期**：提交按钮禁用，或点击后提示「请填写联系方式」+「请填写故障描述」，焦点跳到第一个错误字段
- **优先级**：P0

### TC-11 工单提交成功（含上门字段）
- **前置**：填完联系方式、描述，选择「需要上门」
- **步骤**：提交
- **预期**：
  - 跳转成功页，显示工单号 `TK+8位日期+4位序号`（如 TK202610190001）
  - 提示「售后会在 24 小时内联系您」
  - **后台详情里 `need_on_site` 为「是」**（验证 v1.1 新增列已落库）
- **优先级**：P0

### TC-12 关键词筛选命中
- **前置**：某组合下 5 条故障，其中 2 条标题含「噪音」
- **步骤**：关键词框输入「噪音」
- **预期**：列表实时过滤为 2 条（≤300ms 防抖），清空后恢复 5 条，全程不重新请求接口
- **优先级**：P0

### TC-13 关键词无结果 → 空态 + 未命中日志
- **前置**：同组合下无任何含「漏水」的故障
- **步骤**：输入「漏水」
- **预期**：
  - 列表区显示空态「没有匹配「漏水」的故障…」
  - **DB 中新增一条 `query_logs`：`hit=false`、`raw_query='漏水'`、product_id/part_id 正确**
  - 30 秒内重复输入同一关键词不重复写日志
- **优先级**：P0

### TC-14 未发布故障前台不可见
- **前置**：某故障 `is_published=false`
- **步骤**：前台按该产品+零件查询，并直接访问 `/fault/{id}`
- **预期**：列表不出现；直接访问返回 404 页面，不泄露内容
- **优先级**：P0

### TC-15 附件下载
- **前置**：故障含 `维修手册.pdf`
- **步骤**：点击附件
- **预期**：浏览器下载，文件名与页面显示一致，Nginx 返回 200（非 403/404）

### TC-16 检索词随详情透传

- **预期**：URL 为 `/fault/{id}?q=噪音`，`query_logs` 中该条记录的 `raw_query='噪音'`、`hit=true`

- **预期**：响应均含 `detail`（中文可读）与 `code`（稳定机器码），无堆栈信息
- **优先级**：P1

## 4. 部署测试（5 条）

### TC-50 干净环境启动
- **前置**：干净 Ubuntu 22.04，仅装 Docker 与 Compose
- **步骤**：
  1. 拷贝 deploy 目录
  2. `cp .env.example .env`，改 `DB_PASSWORD`（openssl rand -hex 24）、`JWT_SECRET`（openssl rand -hex 32）、`ADMIN_INIT_PASSWORD`
  3. `mkdir -p data/uploads data/pg`
  4. `docker compose up -d`
  5. 等待 db 与 backend healthy 后执行 `docker compose run --rm init`
- **预期**：
  - **4 个容器**（db / backend / frontend / nginx）全部 running，db 与 backend 为 healthy
  - `init` 任务退出码 0，输出"已创建管理员"
  - `http://服务器IP/` 显示客户查询页
  - `http://服务器IP/admin` 显示登录页
  - 用 `.env` 里的 `ADMIN_INIT_PASSWORD` 能登录成功（不是任何硬编码默认值）
  - 全过程 ≤ 5 分钟
- **优先级**：P0

### TC-51 重启恢复
- **步骤**：`docker compose restart`，再重启服务器
- **预期**：服务自动起来，数据不丢，`restart: unless-stopped` 生效
- **优先级**：P0

### TC-52 备份与恢复
- **前置**：按 `docs/04-运维与运营/备份恢复方案.md §2` 创建 `/opt/fault-system/backup.sh`
- **步骤**：
  1. 跑一次 backup.sh，确认 `backups/` 下生成 db_*.sql.gz 与 uploads_*.tar.gz 且体积合理
  2. 停掉 db 容器再跑一次，确认脚本退出码非 0 且不产生"成功"文件（验证 pipefail）
  3. 造新数据后按 §4.1 恢复（含 DROP SCHEMA 与 ON_ERROR_STOP=1）
- **预期**：数据回到备份时刻；附件可下载；`ticket_status_logs` 条数与备份前一致；恢复过程无 "already exists" 报错
- **优先级**：P1

### TC-53 初始化脚本幂等
- **步骤**：连续执行 `docker compose run --rm init` 三次
- **预期**：第一次创建，后两次输出「已存在，跳过」；`users` 表始终 1 条 admin；已改过的密码不被覆盖；未设置 `ADMIN_INIT_PASSWORD` 时退出码为 2 且不建号
- **优先级**：P0

### TC-54 SPA 路由与静态资源
- **步骤**：直接访问并刷新 `/admin/faults/edit/1`、`/fault/1`
- **预期**：均正常渲染，不出现 404；`/uploads/xxx.jpg` 返回 200 且带 `Cache-Control: public, immutable`
- **优先级**：P0

## 6. 性能与安全（4 条）

### TC-70 查询响应 P95
- **前置**：5 万条故障、50 万条 query_logs 的造数环境
- **步骤**：用 k6/JMeter 对 `/api/faults`、`/api/faults/{id}` 各压 5 分钟
- **预期**：P95 < 500ms，错误率 < 0.1%
- **优先级**：P0

### TC-71 100 并发
- **步骤**：100 并发持续查询 10 分钟
- **预期**：无 5xx，无连接池耗尽告警，后端内存 < 1G
- **优先级**：P1

### TC-72 XSS 注入
- **步骤**：在故障标题、现象、步骤中录入 `<img src=x onerror=alert(1)>`，并在工单描述中提交同样内容
- **预期**：前台与后台均**按纯文本显示**，不弹窗、不执行（验证未使用 `v-html`）
- **优先级**：P0

### TC-73 上传目录安全
- **步骤**：上传名为 `../../etc/passwd.jpg`、`.php.jpg` 的文件；尝试直接访问 `/uploads/../.env`
- **预期**：文件被重命名为随机串存储；路径穿越返回 403/404；`/uploads/` 下不可执行脚本
- **优先级**：P0

## 7. 补充用例（v1.2 第二轮复审增补，13 条）

> 这 13 条填补第一轮遗漏的覆盖缺口：编辑/删除路径、脱敏、第二类空态、并发与事务、安全基线、角色口径。

### TC-55 空组合（未输关键词）未命中上报
- **前置**：某产品+零件组合下没有任何已发布故障
- **步骤**：选完产品与零件，关键词留空
- **预期**：
  - 显示空态"该零件暂无故障记录，可提交工单由售后跟进"
  - DB 新增一条 `query_logs`：`hit=false`、`raw_query IS NULL`、product_id/part_id 正确
  - 看板"未命中检索词"中该记录归入 `(未输入关键词)`，不出现产品名/零件名
- **优先级**：P0

### TC-56 工单列表脱敏与关键词筛选
- **前置**：一条工单联系方式为 `13800138000`，工单号 `TK202610190001`
- **步骤**：查看列表；用 `8000` 搜索；点开详情
- **预期**：列表显示 `138****8000`；关键词 `8000` 能命中该条；详情显示完整 `13800138000`
- **优先级**：P1

### TC-57 故障编辑（步骤整体替换）
- **前置**：一条故障有 3 个步骤
- **步骤**：编辑为 2 个步骤并改标题，保存
- **预期**：`solution_steps` 变为 2 条（不是追加成 5 条）；`updated_at` 更新；前台刷新后同步
- **优先级**：P0

### TC-58 删除故障后引用置空
- **前置**：故障 F 被一条工单引用、且有 2 条查询日志
- **步骤**：删除 F
- **预期**：删除成功；`tickets.fault_id` 与 `query_logs.fault_id` 变为 NULL；工单描述与原查询计数保留（不报 500、不级联删工单）
- **优先级**：P1

### TC-59 删除受引用阻止
- **步骤**：删除有故障的零件；把产品型号改成已存在的型号后保存
- **预期**：零件删除返回 409 `DELETE_BLOCKED` 且故障仍在；产品改型号返回 409 `MODEL_DUPLICATED` 并在型号字段内联提示
- **优先级**：P1

### TC-64 鉴权覆盖率（参数化遍历）
- **步骤**：按 API 契约 §10 列出的 35 个需鉴权端点，逐个不带 token 调用
- **预期**：全部返回 401 `AUTH_TOKEN_EXPIRED`；误把任何一个公开接口（products/parts/faults/tickets/query-logs/health/login）算进受保护集合则判失败
- **优先级**：P0

### TC-65 安全基线静态检查
- **步骤**：① `SELECT password_hash FROM users` ② 全仓 `grep -ri "admin123\|Admin@12345"` ③ 检查 `.env` 与镜像
- **预期**：① 值为 `$2b$` 开头的 60 字符 bcrypt 串 ② 仅测试文档允许出现，代码与配置无硬编码 ③ `JWT_SECRET` 长度 ≥ 32 且非默认值
- **优先级**：P0

### TC-66 SQL 注入探测
- **步骤**：对 `GET /api/faults` 的 `q`、`GET /api/admin/tickets` 的 `keyword` 传入 `' OR 1=1 --`、`%' AND 1=1 --`
- **预期**：按字面量处理并返回空结果或参数化匹配，不报 500、不返回全表、DB 日志无语法错误
- **优先级**：P0

### TC-67 并发建单唯一性
- **步骤**：50 个并发请求同时 `POST /api/tickets`
- **预期**：50 个 `ticket_no` 全部唯一且序号连续；无 500；无重复单
- **优先级**：P0

### TC-68 详情事务一致性
- **步骤**：模拟写 `query_logs` 失败（如临时断开日志表写入权限）后访问故障详情
- **预期**：`view_count` 与日志在同一事务内，二者要么都成功要么都回滚；接口返回 500 而非"计数涨了但没日志"
- **优先级**：P1

### TC-69 TOP10 窗口口径
- **前置**：故障 A 历史查看 500 次但近 7 天 0 次；故障 B 历史 10 次但近 7 天 30 次
- **步骤**：看板切到"近 7 天"
- **预期**：B 排在 A 前面；柱状图数值取 `period_views`（30 / 0），不是历史 `view_count`
- **优先级**：P1

### TC-74 角色权限口径
- **前置**：用 `agent` 角色账号登录
- **预期**：v1.4 起按四角色权限矩阵执行，`agent` 只拥有 `ticket:read` / `ticket:write` / `fault:read`，不能访问产品管理、零件管理、看板与用户管理；细化步骤与矩阵断言见 TC-80、TC-81
- **优先级**：P2

### TC-75 改密边界
- **步骤**：① 新密码与原密码相同 ② 两次输入不一致 ③ 新密码 7 位
- **预期**：① 400 `PASSWORD_SAME` ② 前端拦截，不发请求 ③ 422 `VALIDATION_ERROR`；三种情况密码均未变
- **优先级**：P1

## 8. 权限、产品线与迁移（v1.4 新增，17 条）
