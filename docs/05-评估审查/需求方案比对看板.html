P0 阻塞项（开工前必修）

P0-1管理员密码是编造的假哈希

schema.sql:147 写入的 bcrypt 串为手工占位值，长度与字符分布均不符合算法输出。容器初始化后 admin/admin123 登录必然 401，TC-50 干净环境启动测试必失败。

修复：新增 init_admin.py 启动时生成真实哈希 upsert，删除 SQL 内 INSERT ／ 0.2 人天

P0-2工单「是否上门」无处落库

接口收 need_on_site（API:247），表里没有这一列（schema:106-121）。ORM 严格映射会直接报错，宽松处理则静默丢数据 —— 后台永远看不到用户的上门意愿。

修复：加列 need_on_site BOOLEAN DEFAULT FALSE，补契约与用例断言 ／ 0.1 人天

P0-3「未命中词」没有数据来源

一期客户侧只有三级下拉，没有输入框；GET /api/faults 强制双必填；唯一的写日志点在详情页（此时必有 fault_id，hit 恒为 true）。hit=false 的记录永远不会产生，看板表格恒空。

修复：三选一 —— A 空结果时补写日志／B 加选填关键词框／推荐 C 一期砍掉 ／ 需产品裁决

P0-4工单详情缺接口

页面 P-12 要求「详情抽屉：完整上下文 + 处理备注」，但契约只有列表接口，返回体不含 description／remark。抽屉打不开。

修复：新增 GET /api/admin/tickets/{id}，返回工单全字段 + 关联产品/零件/故障名 ／ 0.3 人天
