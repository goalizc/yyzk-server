## 二、已修（4 项）

### 2.1 【严重】英文「复制方案文本」里的链接指向中文页面

**现象**（实测剪贴板内容）：

```
Full illustrated solution: http://localhost/faults/14
```

英文客服把这段文本复制给英文客户，客户点开是**中文界面**。这条链接是整段文本唯一的可点击
出口，等于把英文客户送回中文页——比界面漏译严重得多。

**根因**：`utils/faultCopy.js` 手工拼 `` `${origin}/faults/${id}` ``，绕过了路由层的语言前缀。
站内跳转都走 `localeRoute()` 所以没暴露，**字符串 URL 这条路径没人管**。

**修复**：新增 `locales/index.js` 的 `localeHref(path)`，与 `localeRoute` 分工明确：

| 场景 | 用哪个 | 返回 |
|---|---|---|
| 路由跳转（`router.push`） | `localeRoute(name, params, query)` | 路由对象 |
| 拼进字符串的 URL（剪贴板、`window.open`、分享） | `localeHref(path)` | `/en/faults/14` |

**验证**：单元测试断言英文文本含 `/en/faults/123` 且**不含** `/faults/123`；
并在真实浏览器点「Copy solution」读剪贴板、点「Open customer page」抓弹窗 URL，
两处都是 `http://localhost/en/faults/14`。反向验证：改回无前缀，用例立即失败。

### 2.2 【严重】英文复制模板此前零测试

`utils/faultCopy.spec.js` 原有 4 条用例，**全部中文**。测试环境把语言锁在 `zh-CN`，
所以英文模板写错、占位符漏了、链接缺前缀，一条都不会红。而这是英文客服每天要用的动作。

**修复**：新增 3 条英文用例（模板走英文 + 业务数据仍是中文、链接带 `/en`、中文环境不带前缀）。

### 2.3 【中】英文单复数语法错误

`{count} people viewed` 在 count=1 时输出 **"1 people viewed"**；同类还有
`1 possible faults found`、`1 solutions viewed`、`Product has 1 fault(s)`。
这类文案出现在客户侧方案页顶部，是"外行一眼看出没做本地化"的位置。

**修复**：用 vue-i18n 原生复数（`单数 | 复数`），调用处从传对象改为传数字：

```js
// 之前：消息只有一段，任何数量都用复数
$t('common.count.viewed', { count: fault.view_count })

// 现在：t(key, n) 选段并绑定 {count}
$t('common.count.viewed', fault.view_count)
```

覆盖 5 条：`viewed`、`foundCount`、产品/零件的 `deleteBlocked`（带命名参数
`t(key, n, { name })`）。统计页的 `viewedSub` 因为数字已格式化（字符串），
无法参与复数选择，改写为计数中性的 `Solution views: {count}`。

配套改了两处测试基础设施：
- 占位符一致性断言改为**按集合比较**——英文复数两段里 `{count}` 出现两次，中文一段只出现一次，
  按数组比会误报
- 新增「复数变体不得引入中文没有的占位符」，防止某一段写成 `{total}` 然后渲染出字面量

### 2.4 【中】「打开客户页」同样缺语言前缀

`FaultReaderDrawer.openCustomerPage()` 用 `window.open('/faults/' + id)`，英文后台点开是中文页。
与 2.1 同一根因，一并改用 `localeHref`，实测弹窗落在 `/en/faults/14`。

## 四、发现但未修（需要决策或价值低）

### 4.1 【低】10 个死 key（占 1.8%）

`common.action.add / search / back / submit / view / upload`、`common.empty.none`、
`admin.ticket.detail.save`、`admin.product.modelDuplicated`、`admin.user.grant.copy`。

后三个是**重复源**：`modelDuplicated` 与 `error.MODEL_DUPLICATED` 表达同一件事，
`grant.copy` 与 `common.action.copy` 同义。两个地方维护同一句话，改一处就漂移。
建议下次改动该页时顺手删掉，不建议为删而单独提交。

### 4.2 【低】千分位只在看板做了

`formatNumber()` 已用于看板，但方案页的 `{count} people viewed` 仍直接插值：英文显示 `2468`
而不是 `2,468`。另外 `formatNumber` 里硬编码 `toLocaleString('zh-CN')`——zh 与 en 的分隔符恰好
相同所以看不出问题，但语义上应跟随当前语言。

### 4.3 【低】首屏静态 `lang` 与标题是中文

`index.html` 写死 `<html lang="zh-CN">` 与中文 `<title>`。直链 `/en/...` 时，JS 执行前有一瞬是中文
（屏幕阅读器先按中文处理，浏览器可能提示"是否翻译"）。JS 一加载就纠正，实际影响很小。

### 4.4 【低】`check_i18n.py` 只查中文

它的职责是"不许新写中文"，**不查写死的英文**。如果有人写 `placeholder="Search"`，
脚本会通过，而中文界面会出现英文。本次静态扫描确认当前 0 处，但没有闸门保障。
若要把这类也拦住，需要给脚本加"模板里非绑定的英文属性值"规则——误报会较多，暂不做。

### 4.5 【低】`fault` 与 `problem` 混用

`public.js` 里既有 `Related problem`，又有 `possible faults found`。语义上还算能区分
（fault = 故障库实体，problem = 客户遇到的问题），但同一屏出现两种说法，对外前建议统一口径。
`Issue`（发放临时授权）与 `problem` 同屏也可能引起误解，可考虑改成 `Grant`。

### 4.6 【低，非国际化】成功页复制工单号没有 HTTP 兜底

`TicketSuccess.copy()` 直接用 `navigator.clipboard`，内网 HTTP 环境下它是 `undefined`，
只会提示"复制失败，请手动记录"。而 `utils/clipboard.js` 已有 textarea 兜底（方案文本在用），
这里没用上。与本次国际化无关，但同一类问题，记录待办。

## 五、审查过程中发现的两个"检测器说谎"

审计结论的可信度取决于检测手段本身，这两次都差点得出错误结论，记录备查。

### 5.1 属性扫描器把 `:sub-title` 当成 `title`

首版正则用 `(?<!:)` 排除动态绑定，但没排除 `-`。结果 `:sub-title="..."` 里的
`title` 被当作裸属性匹配，`:start-placeholder` 同理，一次报了 8 处"写死的英文字面量"，**全是假阳性**。
边界改成 `(?<![\w:.\-])` 后归零。

### 5.2 折行检测用高度判据 100% 假绿

`el-form-item` 行高锁死 32px，label 折行后 `rect.height` 仍是 32，只有 `scrollHeight` 翻倍。
第一版用高度判据跑出"无折行"，与截图里的两行文字矛盾。改成 `scrollHeight >= 1.5 × line-height`
后才发现真问题。详见 `docs/02-技术设计/国际化设计.md` §3.9。

**教训**：检测器本身也要做反向验证。两处都是先"跑绿"，再用已知缺陷去证伪才发现。

## 六、刻意保留（不是缺陷，避免以后被当 bug 改掉）

| 项 | 原因 |
|---|---|
| 业务数据（产品名/故障正文/排查步骤）不翻译 | 存数据库、运营录入；需要 `translations` 表 + 业务方提供译文 |
| 日期格式不随语言变（`2026-10-23 11:10`） | 纯数字格式无歧义；`en-US` 的 `10/23` 与 `en-GB` 的 `23/10` 顺序相反，反而更易误读 |
| 一码多义的错误码英文只给通用文案 | `NOT_FOUND` 覆盖多种资源，英文拿不到"哪个对象不存在" |
| 英文环境不显示后端 `detail`（改走字典） | 后端 `detail` 是中文；字典给通用英文，字段级定位会丢失，属已知代价 |
| `StatsDashboard` 的 `BLANK_QUERY = '(未输入关键词)'` | 与后端约定的归一化比较值，翻译会导致统计匹配失效 |
