## 4. 复审新发现（已修）

### A-1 `if (faultId)` 把 id=0 当假值丢弃（回归）

`StatsDashboard.vue` 的柱状图点击：

```js
const faultId = params?.data?.faultId
if (faultId) { router.push(...) }   // id=0 是合法 id，会被静默丢掉
```

改为显式判空：

```js
if (faultId === undefined || faultId === null) return
```

**为什么第一轮没抓到**：当时的测试用手搓的事件对象 `{ data: { value: 68, faultId: 21 } }` 驱动
click，与 `setOption` 里真实写入的 series data 完全脱钩——就算 series 里没带 `faultId`、
就算判断写成 `if (faultId)`，测试照样通过。属于典型的"假绿"。

复审后该用例改为从 `option.series[0].data[0]` 取真实对象，并补了 id=0 与空 data 两个用例。

### M-1 修复不完整（已补齐）

上一轮修 `PASSWORD_SAME` 时仍保留了 `validateField` 调用，而校验器是"通过就 `callback()`"，
新一轮校验通过反而把刚写入的 `newPasswordError` 清空。改为校验器第一优先级读
`newPasswordError`，并把错误的 `callback(new Error(msg))` 改成 `callback(msg)`——
async-validator 拿到 `Error` 只把 message 存成裸字符串，Element Plus 读不到 `.message`
就不渲染。

### 测试环境限制（已确认，非代码问题）

- happy-dom 下 `el-form-item` 的任何报错形式（`error` prop 与 `validateMessage`）**都不渲染到 DOM**。
  已用两个最小复现文件验证。相关用例改为断言 `setupState` 上的字段错误状态，并另用
  `is-error` class 断言 `PASSWORD_SAME` 的场景（该 class 会正常渲染）。
- `el-dialog` 懒渲染：不先打开弹窗，`formRef` 为 `null`，`validate()` 返回 `undefined`，
  `onSubmit` 会静默 return。测试的 `fillForm` 必须先打开弹窗——这一点已在 helper 上注释。

## 6. 审查中确认无问题的关键点

- **无 `v-html`**，全仓 grep 确认
- 工单状态可选项严格按契约 §5 状态机约束，`closed` 终态下拉禁用并给文案
- 状态变更强制备注（前端拦 + 后端校验双保险）；纯备注/上门变更不强制
- 处理人三分支：显式传 `assignee_id` = 转派；不传且无人 = 认领；不传且有人 = 保持。
  payload 里**从不**主动塞 `assignee_id`，避免误改归属
- 统计口径：解决率分母为 `view_queries`（`hit=true`）而非 `total_queries`；`days=0` 表示全部
- 列表分页统一 `{total, page, page_size, items}`，后台 `page_size` 上限 100
- 删除拦截顺序为"先判 `fault_count` 只提示 → 再确认删除"，不让用户白点一次确认
- 上下架开关失败后重拉列表回滚，不留下与服务端不一致的乐观状态
- 附件/配图只接受后端白名单后缀，前端镜像只做提前拦截，不替代后端校验
