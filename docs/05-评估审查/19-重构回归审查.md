## 二、修了什么

### 2.1 【严重】新建/编辑用户无法选择角色

**现象**：角色下拉**能点开，但一个选项都没有**。英文界面同样是空的。

**根因**：国际化批 2 把角色文案从常量改成语言包，脚本批量替换时只替换了**第一处**：

```
筛选下拉（第 10 行）  v-for="item in roleOptions"   ← 已替换
弹窗下拉（第 113 行） v-for="item in ROLE_OPTIONS"   ← 漏了
```

`ROLE_OPTIONS` 在批 2 已被删除，`v-for` 遍历 `undefined` **不报错、不警告**，
结果就是空列表 —— 一个"静默到极致"的缺陷：构建通过、lint 通过、单测全绿，
只有人真去点那个下拉才会发现。

**为什么单测没抓到**：原有用例断言的是**表格里**的角色文案（`一线客服`），
不是弹窗里的选项。测的是同一个概念的两个渲染位置，只测了一个。

**修复**：弹窗改用 `roleOptions`。

**新闸门**：`UserList.spec.js` 断言弹窗内角色选项数为 4（加上顶部筛选共 8 个）。
选项为空时立刻红。

### 2.2 【中】英文界面「删除产品线」按钮超出弹窗边界

**现象**：新建/编辑用户弹窗里，产品线分配行的 Delete 按钮跑到弹窗右侧外面。

**根因**：分配行三个控件都是写死宽度 —— 下拉 180 + 日期 160 + 按钮。
中文「删除」2 个字、英文 "Delete" 更宽，行宽从 438px 涨到 462px，**溢出 24px**。

另有一个隐蔽点：日期选择器的 `.date { width: 160px }` **根本没生效**，
被 Element 的 `.el-date-editor.el-input { width: 220px }` 压掉了（两者权重相同，
后加载的赢），实际占 220px。

**修复**：
- 下拉改为可伸缩（`flex: 1 1 140px; min-width: 0`）
- 日期固定 150px，选择器加 `.assignment-row` 前缀压过 Element 的规则
- 行允许换行，任何语言都不会溢出

**新闸门**：`e2e/i18n-layout.spec.js` 新增「英文界面弹窗内容不横向溢出」，
覆盖 6 个弹窗（含加一行产品线分配的用户弹窗）。这条守卫在修复前**当场失败**并报出
`新建用户（含产品线分配行）: 横向溢出 24px`，与用户描述一致。

## 三、扫描方法（可复现）

### 3.1 dev 模式收控制台

生产构建会剥掉 Vue 的警告，所以这类"模板引用了不存在的变量"在生产里**完全静默**。
用 `vite dev` 起一个指向同一后端的实例，逐页逐弹窗收集 `console.warning/error` 与 `pageerror`：

```
[warning] Property "ROLE_OPTIONS" was accessed during render but is not defined on instance.
```

这条就是 §2.1 的现场。**这类缺陷只有 dev 模式能看见**——值得作为常规检查手段。

> dev server 的 `/api` 代理默认指向 `localhost:8000`，而本机后端只在 nginx 的 80 端口
> 暴露。临时用一个独立配置文件覆盖代理目标即可，不必改仓库里的 `vite.config.js`。

### 3.2 每个下拉逐个点开

"能点开但没有选项"是一类特定故障，静态和单测都看不出来。逐个 `el-select` 点开数
`.el-select-dropdown__item` 就能发现。

### 3.3 每个弹窗量溢出

英文比中文宽是常态。判据用 `body.scrollWidth - body.clientWidth`（>0 即溢出）。
中文下量不出来，**必须切英文**。

## 四、这次为什么没被拦住（三个机制缺口）

1. **批量替换只替换第一处**。脚本里用 `replace(old, new, 1)` 时，多处同名文本只改一处，
   其余静默保留旧引用。**批量替换后必须全文 grep 一遍**。
2. **单测只覆盖了同一概念的一个渲染位置**。表格断言过了，不代表弹窗里的同一份数据没问题。
3. **生产构建剥掉警告**。缺变量这类问题在生产环境没有任何信号，只能靠 dev 模式或静态扫描。
