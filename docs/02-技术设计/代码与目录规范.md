# 代码与目录规范

## 1. Git 规范

### 分支策略
| 分支 | 用途 |
|---|---|
| main | 生产分支，保护，只接受 merge |
| develop | 开发集成分支 |
| feature/xxx | 功能分支，从 develop 切出 |
| hotfix/xxx | 紧急修复，从 main 切出 |

### Commit 格式
```
<type>: <subject>

type: feat / fix / docs / style / refactor / test / chore
```
示例：
- `feat: 新增故障知识库 CRUD 接口`
- `fix: 修复零件级联下拉不刷新问题`

### Code Review
- feature 分支合并到 develop 前，至少 1 人 review
- 不允许直接 push 到 main

## 2. 后端代码规范

### Python 风格
- PEP 8
- 行宽 100 字符
- 文件、函数、变量：snake_case
- 类：PascalCase
- 常量：UPPER_SNAKE_CASE

### FastAPI 项目结构约定
```python
# main.py
from fastapi import FastAPI
from app.api import auth, public, admin, stats

app = FastAPI(title="售后故障诊断系统", version="1.2.0")
app.include_router(auth.router, prefix="/api/auth", tags=["鉴权"])
app.include_router(public.router, prefix="/api", tags=["公开"])
app.include_router(admin.router, prefix="/api/admin", tags=["后台"])
app.include_router(stats.router, prefix="/api/admin/stats", tags=["统计"])
```

### 模型层示例
```python
# models/fault.py
from sqlalchemy import Column, Integer, String, Text, Boolean, ForeignKey, JSONB, TIMESTAMP
from sqlalchemy.dialects.postgresql import TIMESTAMP as TSTZ
from sqlalchemy.sql import func
from app.database import Base

class Fault(Base):
    __tablename__ = "faults"

    id = Column(Integer, primary_key=True)
    product_id = Column(Integer, ForeignKey("products.id"), nullable=False, index=True)
    part_id = Column(Integer, ForeignKey("parts.id"), nullable=False, index=True)
    title = Column(String(200), nullable=False)
    symptom = Column(Text)
    root_cause = Column(Text)
    solution_steps = Column(JSONB, default=list)
    required_tools = Column(String(200))
    needs_professional = Column(Boolean, default=False)
    attachment_urls = Column(JSONB, default=list)
    view_count = Column(Integer, default=0)
    resolved_count = Column(Integer, default=0)
    is_published = Column(Boolean, default=True, index=True)
    created_at = Column(TSTZ(timezone=True), server_default=func.now())
    updated_at = Column(TSTZ(timezone=True), server_default=func.now(), onupdate=func.now())
```

> 时间列必须用 `TIMESTAMP(timezone=True)` / `DateTime(timezone=True)`，与 schema 的 `TIMESTAMPTZ` 对齐。
> 只写 `TIMESTAMP`（无时区）会与契约的 `+08:00` 冲突，且跨时区部署会错 8 小时。

### 业务逻辑放哪
- 简单 CRUD：直接在 router 里写
- 复杂逻辑抽 `services/` 层，已有：`ticket_no.py`（工单号生成）、`query_log.py`（日志与未命中口径）、`stats.py`（解决率等统计口径）
- 不允许在 router 里写超过 50 行的函数

### 错误处理约定
- 业务异常统一抛 `core.exceptions.BusinessError(code, detail, status)`
- 全局异常处理器转换为 `{"detail": ..., "code": ...}`，禁止把堆栈返回给前端
- 新增错误码必须先登记到 `docs/02-技术设计/API接口契约.md` §7，前端才能识别

### 时间处理约定
- 模型字段一律 `TIMESTAMPTZ`
- 代码中统一用带时区的 `datetime.now(timezone.utc)`，禁止 `datetime.now()` 裸调用
- 序列化输出时区为 `Asia/Shanghai`，格式 `ISO 8601`（如 `2026-10-19T10:00:00+08:00`）

## 3. 前端代码规范

### Vue 3 风格
- `<script setup>` Composition API
- 组件名 PascalCase
- Props 必须带类型
- API 请求统一放 `src/api/`，组件里不直接写 axios
- **禁止使用 `v-html` 渲染任何运营录入或用户提交的内容**（故障标题/现象/步骤/工单描述），一律插值渲染
- 列表与详情页需实现三态：加载中骨架、空态（带引导动作）、错误态（可重试）
- 详情页必须保存接口返回的 `query_log_id` 并在反馈时回传
- 统一使用 `src/utils/format.js` 处理时间与百分比，避免各页面各写一套

### 国际化（强制：新增功能必须支持）

> 背景：一期为纯中文，v1.7 完成中英双语改造（客户侧 + 后台全部页面）。
> 此后**任何面向用户的文案都不允许硬编码中文**，否则英文界面会漏出中文。
> 完整设计见 `docs/02-技术设计/国际化设计.md`。

**9 条硬要求：**

1. **文案一律入语言包**：放 `src/locales/{zh-CN,en-US}/`，组件里用 `$t('key')` 或
   `const { t } = useI18n()`。**两种语言必须同时加**——`src/locales/locale.spec.js`
   会校验键集合与占位符一致，漏一边直接红。
2. **key 必须是完整字面量**：
   ```js
   // ❌ 扫描脚本、翻译平台、键完整性检查全部失效，只在特定数据下才运行时报错
   $t('ticket.status.' + row.status)

   // ✅ 通过映射表，key 仍是字面量
   const STATUS_KEYS = { open: 'common.status.open', processing: 'common.status.processing' }
   $t(STATUS_KEYS[row.status])
   ```
3. **动态片段用命名插值**，不要拼字符串：语言包写 `型号 {model} 已存在`，
   调用处 `t('x.y', { model })`。
4. **表单标签宽度按语言给**：`const labelWidth = useFormLabelWidth('88px', '120px')`。
   不要写死像素（英文标签比中文长 1.5–2 倍）；也**不要用 `label-width="auto"`**——
   实测它让同一表单内各标签宽度不同（Product 70px / Requires a professional 159px），
   标签不对齐，值的起始位置参差，比折行更难读。
5. **表格列宽按英文核对**：英文普遍更长（`In progress` / `On-site` / `Reset password`），
   中文时代的列宽会截断英文。
6. **后端新增错误码**：先登记 API 契约 §7 → 再补 `locales/*/error.js`（两份）。
   `locale.spec.js` 会扫描 `backend/app` 的 `BusinessError` 码与前端字典比对，漏了会红。
7. **拼进字符串的 URL 必须带语言前缀**：用 `localeHref('/faults/9')` →
   `/en/faults/9`。剪贴板文本、`window.open`、分享链接都属于这一类。
   路由跳转用 `localeRoute()`。手拼 `` `/faults/${id}` `` 会让英文客户点开中文页
   （已发生，见 `docs/05-评估审查/18-国际化全量审查.md` §2.1）
8. **英文文案注意单复数**：`{count}` 类的句子用 vue-i18n 复数语法
   `'1 fault | {count} faults'`，调用处传**数字**：`t(key, n)` /
   `t(key, n, { name })`，不要传 `{ count: n }`（那样永远走第一段）。
   数字已被格式化（字符串）的场合无法选段，改用计数中性的说法（`Views: {count}`）
9. **提交前跑检查**：`python scripts/dev/check_i18n.py`，发现硬编码中文即失败退出。

**例外**：确实不能翻译的值（与后端约定的比较值等），在该行加 `// i18n-ignore` 并写明原因。

```bash
# 提交前固定三查（加上 i18n）
python scripts/dev/check_links.py            # 文档链接
python scripts/dev/check_duplicate_tests.py  # 测试函数重名
python scripts/dev/check_i18n.py             # 硬编码中文
```

### API 封装示例
```javascript
// api/request.js
import axios from 'axios'

const request = axios.create({ baseURL: '/api', timeout: 10000 })

request.interceptors.request.use(config => {
  const token = localStorage.getItem('token')
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})

request.interceptors.response.use(
  res => res.data,
  err => {
    if (err.response?.status === 401) {
      localStorage.removeItem('token')
      location.href = '/admin/login'
    }
    return Promise.reject(err)
  }
)

export default request
```

### 路由守卫
```javascript
router.beforeEach((to, from, next) => {
  if (to.path.startsWith('/admin') && to.path !== '/admin/login') {
    const token = localStorage.getItem('token')
    if (!token) next('/admin/login')
    else next()
  } else {
    next()
  }
})
```

## 4. 命名约定
| 对象 | 约定 | 示例 |
|---|---|---|
| 数据库表 | 复数，snake_case | products / parts / faults / query_logs / tickets / ticket_status_logs / users |
| API 路径 | 复数名词 | /api/products, /api/faults |
| 文件上传 | 日期-随机串 | 20261019-a1b2c3d4.jpg |
| 工单编号 | TK + 日期 + 4 位序号（定长） | TK202610190001 |
| 错误码 | UPPER_SNAKE，模块前缀 | MODEL_DUPLICATED, DELETE_BLOCKED, TICKET_STATUS_INVALID |

## 5. 环境区分
| 环境 | 用途 | 数据库 |
|---|---|---|
| local | 本地开发 | 本地 PostgreSQL |
| test | 测试环境（部署测试） | 测试库 |
| prod | 生产 | 生产库 |

环境变量通过 `.env` 文件区分，代码里不写死连接串。
