## 5. 部署架构

### Docker Compose 服务
| 服务 | 镜像 | 端口 | 数据卷 | 健康检查 |
|---|---|---|---|---|
| db | postgres:15-alpine | 内网 5432 | ./data/pg | pg_isready |
| backend | 自建 Dockerfile | 内网 8000 | ./data/uploads | GET /api/health |
| frontend | 自建 Dockerfile (nginx) | 内网 80 | - | GET / |
| nginx | nginx:1.25-alpine | 80 (对外，443 待证书) | ./data/uploads:ro | GET /health |
| init | 同 backend 镜像 | 一次性（profile: init） | - | - |
| migrate | 同 backend 镜像 | 一次性（profile: migrate） | ./scripts、./migrations:ro | - |

启动顺序：**db healthy → 执行迁移 → backend healthy → nginx 启动**。`migrate` 与 `init` 均为 `docker compose run --rm` 手动/脚本触发的一次性任务；升级与恢复后必须先迁移再起后端。

### 环境变量（.env）
| 变量 | 说明 | 必填 |
|---|---|---|
| DB_USER | 数据库用户 | 是 |
| DB_PASSWORD | 数据库密码（≥16 位） | 是（缺失则 compose 拒绝启动） |
| DB_NAME | 数据库名 | 是 |
| JWT_SECRET | JWT 签名密钥（openssl rand -hex 32） | 是（缺失则拒绝启动） |
| JWT_ALGORITHM | HS256 | 是 |
| JWT_EXPIRE_HOURS | 24 | 是 |
| TZ | Asia/Shanghai，影响全部时间字段与备份窗口 | 是 |
| ADMIN_USERNAME | 初始化管理员账号，默认 admin | 否 |
| ADMIN_INIT_PASSWORD | 初始密码（≥8 位），仅 init 任务使用；脚本校验，缺失则退出码 2 | 跑 init 时是 |
| ADMIN_REAL_NAME | 管理员显示名 | 否 |
| MAX_UPLOAD_MB | 上传上限，默认 20（需与 Nginx 保持一致） | 否 |

## 6. 安全设计
1. 所有后台接口走 JWT 鉴权（含工单详情、改密）
2. 密码 bcrypt 哈希，不存明文；**初始密码由脚本在运行时生成哈希**，不在 SQL 中写死
3. SQL 注入：ORM 参数化查询
4. XSS：前端默认转义；**禁止 `v-html`** 渲染故障内容与工单描述（运营录入视为不可信输入）
5. 文件上传：后缀白名单（.jpg/.jpeg/.png/.pdf/.mp4）+ MIME 双校验，重命名存储，不保留原文件名，上传目录禁止脚本执行
6. 路径穿越：文件名不参与路径拼接，一律用生成的随机名
7. CORS：Nginx 同源部署，后端不开放跨域
8. 限流：`/api/query-logs` 30 次/分钟、`/api/auth/login` 10 次/分钟（burst 5）、`/api/tickets` 10 次/分钟（burst 3），Nginx `limit_req`，超限返回 429 JSON
9. 响应头：`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`；启用 HTTPS 后加 HSTS
10. 登录态：JWT 存 `localStorage`，有效期 24 小时；**空闲 60 分钟自动登出**（详见 §8.3）。这条是客户端防线，只挡"顺手打开没退出的电脑"，不改变 token 在 `exp` 前仍然有效这一事实

## 7. 日志与监控
- 应用日志：Python `logging` 输出 JSON 行到 stdout，字段含 `time / level / request_id / method / path / status / duration_ms`，由 Docker logs 收集
- 访问日志：Nginx 默认日志（保留 7 天，json-file 驱动 10MB × 3 轮转）
- 健康检查：`GET /api/health` 只查 DB 连通性，供容器 healthcheck 与外部拨测使用
- 错误告警：一期不接告警平台，靠 `docker logs` + 备份脚本的邮件检查；二期接 Prometheus + Grafana
- 容量基线：uvicorn `--workers 2`（4 核足够），SQLAlchemy 连接池 `pool_size=5, max_overflow=10`，对应 100 并发目标

## 8. 鉴权与授权层

### 8.1 分层

```
请求 → get_current_user（每次查库校验 is_active）→ require("权限码") → 接口
                     │                                  │
                     │                                  └─ 角色模板 ∪ 临时授权 → 依赖闭包展开
                     └─ users.role → 数据范围 ALL / LINES
```

- **权限码**：按 `资源:动作` 命名，共 15 个，集中定义在 `backend/app/core/permissions.py`。不建数据库表、不加 CHECK 约束 —— 权限是代码行为的一部分，新增权限码只改常量、矩阵与测试，不涉及 DDL。
- **角色模板**：四个角色（`super_admin` / `supervisor` / `agent` / `auditor`）= 固定权限码集合 + 数据范围（`ALL` / `LINES`）。代码中禁止散落角色字符串比较。
- **临时授权**：`user_permission_grants` 按人发放，带 `expires_at` 与 `reason`，到期/收回在每次请求计算时失效；**只增不减**，不可授予 `user:write`，不能超出发放者自身权限。生效权限为角色模板与有效授权的并集，再按依赖闭包补齐（如 `ticket:assign` → `ticket:write` → `ticket:read`）。
- **实时生效**：`get_current_user` 每次请求从数据库读用户，停用、改角色、授权到期均在下一个请求生效，不依赖定时任务。

### 8.2 数据范围

- 数据范围**只作用于工单**：`GET /api/admin/tickets`、`GET /api/admin/tickets/{id}`、`PUT /api/admin/tickets/{id}`。
- `ALL` 不受限；`LINES` 通过 `user_product_lines`（未过期）→ `products.line_id` 计算出可见产品集合，再过滤 `tickets.product_id`。
- 客服未分配产品线 → 可见集合为空，列表 0 条；`product_id` 为空的工单仅 `ALL` 可见；过滤先于关键字搜索；详情与更新同样校验，越权 403 `PERMISSION_DENIED`。
- 改派候选人由 `ticket_scope.assignable_users` 计算：启用 + `ticket:write` + 对工单产品线可见。

### 8.3 会话与空闲超时（v1.4）

| 项 | 现状 | 说明 |
|---|---|---|
| 存储 | `localStorage` 的 `token` / `user` / `permissions` | 关浏览器、关机都不清 |
| 有效期 | JWT `exp` 24 小时 | 过期后后端 401，前端拦截器清凭证回登录页 |
| 空闲超时 | **60 分钟**，`utils/idle.js#IDLE_TIMEOUT_MS` | 超时清凭证 → `/admin/login?reason=idle`，登录页显示"长时间未操作，已自动退出" |
| 提前提醒 | 超时前 2 分钟弹一次 | 防止写故障方案时被无声打断 |
| 多标签 | `lastActiveAt` 存 `localStorage`，各标签共享；监听 `storage` 事件，一个标签登出其余跟着跳 | 否则别的标签还留着工单内容在屏幕上 |

**为什么需要它**：JWT 24 小时有效期正好覆盖"晚上下班 → 次日上班"（17:30 到 09:00 只有 15.5 小时）。凭证存在 `localStorage` 又不会因为关机消失，于是第二天开机、浏览器恢复标签页后，任何人打开这台电脑都能直接进后台看工单（含客户手机号）。

**两处检查，缺一不可**：
1. 路由守卫 `idleRedirect`：进入后台页面前判定。负责"隔夜开机直接打开某页"——用户看不到后台内容一闪而过
2. `Layout` 挂载后的 `startIdleWatch`：运行期每 30 秒检查 + `visibilitychange` 时补判。负责"页面开着没人动"，以及后台标签被浏览器节流的场景

**边界（写清楚，别高估它）**：这是前端行为，token 在 `exp` 前本身仍然有效，改 `localStorage` 或换一台设备就能绕过。它挡的是"同事顺手打开你没退出的电脑"，挡不住"提前把 token 复制走的人"。后者需要服务端会话表（可按人强制下线、看到在线会话）或 `refresh_token` + httpOnly cookie，属二期。

> 用例：`utils/idle.spec.js`（9 条，含"持续操作不触发"）、`router/guard.spec.js#idleRedirect`（5 条）、
> `views/admin/Login.spec.js`（登录成功必须重置计时，否则刚登录就被踢）、
> `e2e/session-idle.spec.js`（3 条：隔夜、刚操作过不误踢、切回标签页补判）。

## 9. 产品线模型

```
product_lines 1 ──< products 1 ──< parts / faults / tickets
      │
      └──< user_product_lines >── users
```

| 表 | 关键字段 | 说明 |
|---|---|---|
| `product_lines` | `name` 唯一、`sort_order`、`is_active` | 停用后不用于新建产品/新授权，已有归属继续有效 |
| `products.line_id` | `NOT NULL`、`ON DELETE RESTRICT` | 取代原 `category`；产品线是数据权限的唯一判定依据 |
| `user_product_lines` | `(user_id, line_id)` 主键、`expires_at` | `NULL` = 长期；到期后该产品线工单立即不可见 |
| `user_permission_grants` | `permission`、`expires_at`、`reason`、`granted_by`、`revoked_at` | 临时授权；过期与收回记录保留追溯 |

> 授权到产品线，不授权到产品型号：未来 `product_versions`、BOM 挂在 `products` 下，授权层无需改动。

## 10. 数据库迁移机制与部署顺序

### 10.1 `schema_migrations`

```
schema_migrations (
    version    VARCHAR(50) PRIMARY KEY,
    applied_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
)
```

- 迁移文件位于 `deploy/migrations/` 目录，按文件名序号顺序执行（`001_`、`002_` …）。
- `deploy/scripts/migrate.py` 读取已应用版本，跳过已完成，逐个在事务中执行并记录；失败即退出（非零码）。用 Python 而非 shell + psql，因为 backend 镜像没有 psql 但有 psycopg2。
- `deploy/schema.sql` 表示**最新目标状态**，末尾把随包发布的迁移版本写入 `schema_migrations`，全新库不会重复执行迁移。
- 旧库升级只靠迁移文件，不写兼容双读逻辑。本次 `001_user_permissions.sql` 建立三张新表、回填并删除 `products.category`、迁移 `users.role` 的 CHECK。

### 10.2 部署顺序（强制）

```
1. docker compose up -d db           # 等 db healthy
2. docker compose run --rm -T migrate
3. docker compose up -d              # 再启动 backend 对外服务
4. 等 backend healthy → 初始化管理员
```

`/api/health` 只做 `SELECT 1`，旧表结构也能返回 ok，不能作为迁移完成的依据；顺序颠倒会让新代码在迁移前对外提供 500。

### 10.3 备份、恢复与回滚

- 迁移前必须用 `backup.sh` 做一次数据库备份；`001` 删除 `products.category`，属不可逆变更。
- `restore.sh` 是 `DROP SCHEMA` 后整库还原；若还原的是迁移前备份，**恢复后必须追加执行 `docker compose run --rm migrate`**，否则新代码对旧表。
- 回滚以「备份还原 + 回退镜像」为准，不写反向迁移脚本。
