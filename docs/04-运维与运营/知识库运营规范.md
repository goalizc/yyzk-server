# 知识库运营规范

> 知识库质量决定系统效果。本规范指导售后团队持续维护故障知识库。

## 1. 录入规范

### 1.1 录入流程
1. 从工单系统导出高频故障（每周一次）
2. 按模板整理成结构化表格
3. 在后台逐条录入
4. 主管审核后发布

### 1.2 字段填写规范

| 字段 | 规范 |
|---|---|
| 产品 | 选具体型号，不要只选大类 |
| 零件 | 选最相关的零件；如果是整机问题，选"整机"或对应模块 |
| 故障标题 | 用户视角的现象描述，如"开机无反应"，不要写"电源模块故障" |
| 现象描述 | 写清楚什么情况下出现、有什么表现，2-3 句话 |
| 可能原因 | 列出 1-3 个可能原因，按概率排序 |
| 解决步骤 | 每步一个动作，可执行；不要写"检查一下电源"，要写"确认电源适配器指示灯是否亮起" |
| 所需工具 | 需要工具就写，不需要写"无" |
| 是否需专业人员 | 涉及拆机、强电、电池更换的，必须勾选 |
| 附件 | 有维修手册、拆解图就上传；没有可以不传 |

### 1.3 步骤写作示例
**好的写法**：
```
1. 确认电源适配器插在通电插座上，适配器指示灯是否亮起
2. 如果指示灯不亮，更换一个插座测试
3. 如果指示灯亮但设备仍无反应，长按开机键 10 秒强制重启
4. 以上都无效，勾选"需要专业人员维修"
```

**差的写法**：
```
1. 检查电源
2. 重启设备
3. 还不行就送修
```

## 2. 审核规范

- 所有新故障方案必须由售后主管审核后才发布
- 审核重点：
  - 步骤是否可执行、不会误导用户
  - 危险操作是否标记了 needs_professional
  - 是否关联了正确的产品和零件
- 审核记录：后台编辑历史里自动留痕

## 3. 定期运营节奏

| 频率 | 动作 | 负责人 |
|---|---|---|
| 每天 | 处理新工单，标记哪些问题知识库能覆盖 | 客服 |
| 每周 | 导出未命中检索词列表，补充 3-5 条新故障 | 售后知识运营 |
| 每周 | 看解决率数据，找出解决率低的方案，优化步骤 | 售后主管 |
| 每月 | 盘点高频故障 TOP 20，更新方案，补充附件 | 售后主管 |
| 每季度 | 产品迭代后，更新旧版本故障方案 | 售后主管 + 产品 |

## 4. 质量指标
| 指标 | 目标 |
|---|---|
| 自助解决率 | ≥ 30%（上线 3 个月后） |
| 高频故障覆盖率（TOP 20 故障都有方案） | 100% |
| 未命中检索词数量（每周新增） | 持续下降 |
| 方案平均解决率 | ≥ 60% |
