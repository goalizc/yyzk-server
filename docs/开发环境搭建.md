# 开发环境搭建

> 目标：任何人拿到这个仓库，能在 15 分钟内跑起后端、前端和一个可用的 PostgreSQL。
> 本文分三种环境，先看你属于哪种，别混用。

| 环境 | 用途 | 数据库 | 能否验证 `docker compose up` |
|---|---|---|---|
| **A. 你的开发机 + Docker**（推荐） | 日常开发、联调 | 容器内 PostgreSQL 15 | ✅ 能 |
| **B. 你的开发机 + 原生安装**（Manjaro/Arch） | 不想装 Docker，或 Docker 受限 | 系统 PostgreSQL | ⚠️ 只能验证 compose 语法 |
| **C. 无 root / 云沙箱** | 只做代码逻辑与 schema 校验 | pglite（WASM PG） | ❌ 不能 |

> **重要**：AI 助手运行的沙箱属于 C 类，安装物是**一次性的**，不能当作开发环境交付。
> 真正可复现的环境定义是：`requirements.txt`、`package.json`、`deploy/`、`.env.example`。

## A. Docker 方式（推荐，与生产一致）

```bash
# 0. 前置：Docker 24+ 与 Compose v2
docker --version && docker compose version

cd deploy
cp .env.example .env
# 改三个必填：DB_PASSWORD（openssl rand -hex 24）、JWT_SECRET（openssl rand -hex 32）、ADMIN_INIT_PASSWORD
mkdir -p data/pg data/uploads
# backend 容器以非 root（uid=10001）运行，uploads 要能写，否则后续上传会 500
sudo chown -R 10001:10001 data/uploads
docker compose up -d
docker compose run --rm init          # 初始化管理员（幂等）

curl -s http://localhost/health       # 期望 ok
docker compose ps                     # 期望 4 个容器 running
```

本地跑后端时不必整栈起，只起 db 就够：

```bash
cd deploy && docker compose up -d db
# 然后把 DATABASE_URL 指向 localhost:5432
```

### 装完先自检

```bash
bash scripts/dev/check_env.sh          # 检查 docker/daemon/compose/端口/.env/目录
bash scripts/dev/check_env.sh --pull   # 额外验证两个基础镜像能否拉取
```

它会把「docker 没装、daemon 没起、不在 docker 组、`.env` 还是占位值、80 端口被占」这类问题
在 `up` 之前就报出来，避免对着一堆容器日志猜原因。

### `--build` 卡住不动怎么办

构建卡住 99% 是**构建容器连不上外网源**，不是镜像写错。两个常见坑：

1. 构建容器**不读**宿主机的 `~/.config/pip/pip.conf` 和 `~/.npmrc`，
   `pip install` 会直连 pypi.org、`npm ci` 会直连 registry.npmjs.org，国内长时间无响应。
   → 镜像里已通过 build args 传入源（pip 官方 / npm npmmirror），可用 `.env` 覆盖。
2. Dockerfile 里写 `# syntax=docker/dockerfile:1` 会让 BuildKit 先去 Docker Hub 拉 frontend 镜像。
   → 本项目**刻意不加**这一行，只用基础语法。

> 实测坑：清华 PyPI 对部分云主机 IP 直接返回 **403 Forbidden**，pip 的报错是
> `from versions: none`（看起来像"包不存在"，其实是源拒绝）。遇到就换源或在 `.env` 里指定。

排查顺序（`--progress=plain` 才能看见卡在第几步）：

```bash
bash scripts/dev/build.sh backend     # 或 docker compose build --progress=plain backend
```

- 停在 `pip install` / `npm ci` → 换源：在 `deploy/.env` 里设 `PIP_INDEX_URL` / `NPM_REGISTRY`
- 停在 `FROM` → 基础镜像没拉到：`docker pull docker.m.daocloud.io/library/python:3.12-slim`
  后 `docker tag` 成 `python:3.12-slim`，或在 `.env` 里直接改 `PYTHON_IMAGE`
- 停在 `transferring context` → 构建上下文过大：确认根目录 `.dockerignore` 生效（不应包含 `.venv`、`node_modules`）

## B. 原生安装（Manjaro / Arch）

系统级安装需要 root。若 `sudo` 需要密码，可用 askpass 让弹窗接收密码：

```bash
# 一次性：装 askpass 并指定给 sudo
sudo pacman -S --needed ssh-askpass
export SUDO_ASKPASS=/usr/lib/ssh/ssh-askpass
# 之后所有 sudo 都可以加 -A 走弹窗：
sudo -A pacman -S --needed postgresql
```

完整步骤：

```bash
# 1. 安装
sudo -A pacman -S --needed postgresql

# 2. 初始化数据目录（只需一次）
sudo -u postgres initdb -D /var/lib/postgres/data --locale=C.UTF-8 -E UTF8

# 3. 启动并设为开机自启
sudo systemctl enable --now postgresql

# 4. 建角色与库
sudo -u postgres psql -c "CREATE ROLE fault LOGIN PASSWORD '换成强密码';"
sudo -u postgres psql -c "CREATE DATABASE fault_db OWNER fault;"

# 5. 应用表结构（用仓库里的 schema.sql，别手写）
psql "postgresql://fault:换成强密码@localhost:5432/fault_db" -v ON_ERROR_STOP=1 \
  -f deploy/schema.sql

# 6. 初始化管理员（本地直接跑脚本）
cd deploy
DATABASE_URL="postgresql+psycopg2://fault:密码@localhost:5432/fault_db" \
ADMIN_INIT_PASSWORD="至少8位" \
python scripts/init_admin.py
```

> Manjaro 的 PostgreSQL 版本随仓库滚动（可能 15/16/17）。`schema.sql` 只用标准 SQL 与
> PG13+ 特性（JSONB、部分索引、`gen_random_uuid`），跨版本无差异。
> 若提示 `pg_stat_statements` 未加载，在 `postgresql.conf` 加
> `shared_preload_libraries = 'pg_stat_statements'` 后重启；或者直接忽略（只影响慢查询视图）。

## C. 无 root 环境（只能校验，不能替代数据库）

用于 CI 或沙箱，验证 `deploy/schema.sql` 是否真的能被 PostgreSQL 接受：

```bash
npm install                                   # 装 @electric-sql/pglite（WASM PG 16）
node scripts/dev/verify_schema.mjs            # 或 npm run verify:schema
```

它会在内存里起一个真实的 PG 引擎，执行 `schema.sql`，然后抽查 11 项：

- 7 张表、24 个索引（含部分索引与表达式索引）
- 工单号 CHECK（3 位被拒 / 4 位通过）
- 状态枚举 CHECK
- 删除故障 → `tickets`/`query_logs` 外键置 NULL
- 删除有零件的产品 → RESTRICT 阻止
- JSONB 默认值、`TIMESTAMPTZ` 类型、视图可查

**局限**：单连接、无并发、无真实认证/网络/扩展生态。只用来防「DDL 写错」，不能替代集成测试。

### 没有 Docker、也没有 PostgreSQL 时怎么跑全栈

同一个 PGlite 可以经 pg 协议对外提供服务（`@electric-sql/pglite-socket`），
于是「起真库 + 跑后端 + 跑前端」在无 root 环境也能做：

```bash
# 1) WASM PostgreSQL：监听 127.0.0.1:55432，首次自动执行 deploy/schema.sql
npm run dev:pg                      # 重建数据目录加 --reset

# 2) 初始化管理员（脚本认 DATABASE_URL）
cd deploy
DATABASE_URL=postgresql+psycopg2://postgres@127.0.0.1:55432/postgres \
ADMIN_INIT_PASSWORD='至少8位' python ../scripts/init_admin.py
cd ..

# 3) 起后端
DATABASE_URL=postgresql+psycopg2://postgres@127.0.0.1:55432/postgres \
JWT_SECRET=$(openssl rand -hex 32) \
.venv/bin/python -m uvicorn app.main:app --app-dir backend --port 8000

# 4) 起前端（/api 已代理到 8000）
cd frontend && npm run dev

# 5) ORM 模型与 schema.sql 是否对齐（JSONB / CHECK / TIMESTAMPTZ / 视图）
DATABASE_URL=postgresql+psycopg2://postgres@127.0.0.1:55432/postgres \
.venv/bin/python scripts/dev/check_orm_pg.py
```

注意三点：

- 引擎是 **PGlite 0.5.10（PostgreSQL 18.6 on WASM）**，项目目标是 PG 15。SQL 行为一致，
  但性能与并发完全不同，**不能**用它做压测结论
- 查询是全局串行的，多请求会排队；`maxConnections` 只是连接数上限，不是并发能力
- 数据落在 `.tmp/pgdata`，换 schema 时用 `--reset` 重建

## 沙箱环境实测结论（供参考，不是你的开发机）

| 能力 | 结果 |
|---|---|
| 用户 | root（uid 0），但 `sudo` 配置损坏（`/etc/sudo.conf` 属主 65534） |
| 系统目录写入 | ❌ 全部被拒（`/etc`、`/opt`、`/usr/local/bin`、`/var/tmp` 均 EPERM） |
| `chown` / `setpriv` 切用户 | ❌ EPERM（PG 拒绝 root 启动，故无法跑原生 PG） |
| Docker | ⚠️ 客户端 29.7.2 已装，但 daemon socket 被沙箱 LSM 拒绝（root 也 `connect: 权限不够`），无法 build/up |
| `/tmp` | ⚠️ 仅 **10MB** tmpfs —— pip/npm 会报「设备上没有空间」，必须 `TMPDIR=$PWD/.tmp` |
| pip / npm 源 | ✅ 可用（清华 PyPI、npmjs） |
| Python / Node | ✅ 3.13.12 / 22.22.2 |

结论：沙箱能完成**写代码 + 单测 + 真库联调（WASM PG）**；
**容器编排、Nginx、健康检查**只能在 A 或 B 环境验证。

## 日常命令

```bash
# 后端
DEBUG=true .venv/bin/python -m uvicorn app.main:app --app-dir backend --reload --port 8000
# DEBUG=true 才会开 /api/docs，默认关闭
.venv/bin/pytest -q
.venv/bin/pytest --cov=app --cov-report=term-missing

# 前端
cd frontend && npm install && npm run dev      # 5173
npm run build

# 校验
npm run verify:schema                          # DDL 是否合法
npm run dev:pg                                 # WASM PostgreSQL（无 Docker 时联调用）
curl -s localhost:8000/api/health
```

### 安装依赖时的坑

沙箱与部分容器环境的 `/tmp` 很小，pip/npm 解包会失败。统一这样装：

```bash
export TMPDIR="$PWD/.tmp"
export npm_config_cache="$PWD/.npmcache"
.venv/bin/pip install --cache-dir "$PWD/.pipcache" -r requirements-dev.txt
npm install
```
